1. **WOFF2 压缩质量按体量自适应**。实测同一份 10MB 中文字体：brotli q11 = 152s/5.18MB，q9 = 15s/5.52MB，q6 = 7s/5.54MB。q11 在 UI 里不可接受，q6 体积只大 0.5%。规则：表体量 > 4MB 用 q6，否则 q11（拉丁字体仍拿最小体积）。

3. **CSS 单一来源**：`css_text` 同时服务面板预览、复制、包内 fonts.css，路径一律按包内目录写。
4. **清单不重新解析字体**：哈希/字符数走 `cache.db`；索引没算过的就留空，宁可空也不现场 parse 整库。
5. 一次最多 200 个字重生成 WOFF2（超了直接报错），避免用户误点整库后卡住。

## 12:10 · 结案：「启动白屏」是本机沙箱注入造成的假象，不是程序 bug

现象
- P10 构建后启动：窗口纯白、无 CSS、`scan.log` 只有 `boot`，没有 `scan_fonts() called`。
- 约 +2 秒必崩，`EBWebView/Crashpad/reports` 每次多一个 ~6.4MB 转储。

定位过程（关键节点）
- 先排除前端：`main.tsx` 换成 0.92KB 极简版、再换成纯 HTML（无 CSS/字体/模块脚本），仍崩 → 与页面内容无关。
- 内联脚本能跑通并上报 `href=http://tauri.localhost/` → HTML 已正常服务；不是资源 404，也不是 CSP。
- 解析 minidump 元数据：`ProcessType=browser`、`ModuleName=msedge.dll`、`SubCode=0x80000003`
  （= STATUS_BREAKPOINT，Chromium 自检失败后 `__debugbreak()` 自杀）。
- 按 MINIDUMP_MODULE_LIST 解析模块表（89 个），发现
  `D:\Program_Files\WorkBuddy\resources\app.asar.unpacked\cli\vendor\sandbox\5.8.6\tsbx.dll`。
- 全进程扫描 `tsbx.dll`：只注入 bash / powershell / python / editor_sdk / zfontmanager，
  **没有**注入 rayburst 及其 webview（它正常）。→ CLI 沙箱把 DLL 注入子进程，连带进了 WebView2
  的 browser 进程，Chromium 校验不过就自杀。

验证
- 改用 `explorer.exe <exe>` 拉起（进程树干净）：`tsbx_injected=False`，6 个 webview 进程健在
  （含 `type=renderer`），`scan_fonts() called / files=284 faces=308 0.02s`，截图界面完全正常。

最终产物
- `index.html` / `main.tsx` / CSP / `lib.rs` 全部还原；`probe` 命令、兜底显示线程、`fontStore` 的
  `trace()`、`make-probe.mjs` 等诊断残留已清空（grep 复核为空）。
- `cargo test --lib` 119 passed / 0 failed；`tsc --noEmit` 通过。
- exe 24,192,512 B（23.07 MB），导入表仅 Windows 系统 DLL；zip 重打为 8,988,357 B。
- 截图归档：`reports/P10-备份与迁移页.png`、`reports/P10-字体库首页.png`。

教训（重要）
- **Tauri / WebView2 程序不要用 `./app.exe` 在工具 shell 里启动做验收**，一律 `explorer.exe <exe>`
  或让用户双击；否则沙箱注入会让 WebView2 崩掉，看起来像「程序白屏」，极易误判成自己的 bug。
- 判断「页面有没有加载」最快的手段：`index.html` 里塞内联脚本 `fetch` 到本地端口上报。
  **跨线程调用 `webview.eval()` 会直接崩掉 WebView2**，别用。
- 单独跑 `cargo build --release` **不会**内嵌前端资源（比 `tauri build` 小约 860KB，会白屏），
  验收必须走 `pnpm tauri build`。

### 「启用至关闭」的行业做法（回答用户提问，已写进 README）

Windows 只有四档作用域，所有字体工具都在这四档里选：
1. HKLM + `C:/Windows/Fonts` —— 全机器，需管理员
2. HKCU + `AddFontResourceW` —— 当前用户，重启仍在，不需管理员
3. `AddFontResourceW` 不写注册表 —— 会话级，注销即失效（**真临时**）
4. `AddFontResourceExW(FR_PRIVATE)` —— 进程私有，别的软件看不见

字由 / 字加这类客户端把字体放在自己缓存目录（省掉管理员），激活时**绝大多数用第 2 档**
而不是第 3 档，原因是：PS/AI/Office 启动时枚举一次字体，之后不刷新（2、3 档都救不了已开的软件）；
写 HKCU 后字体一直有效，客户端崩溃也不影响；第 3 档崩溃后状态更不可控。
判断某工具用哪一档：激活前后 `reg query HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts`。

本程序当前第 2 档 + 退出时删 = 「先装、退出时卸」。改真临时只需在 session 路径跳过
`set_user_entry`（`activation::apply` 里那行），但收益仅「不写注册表」，代价是行为更飘。
