## 0. 结论（TL;DR）

| 决策项 | 结论 |
|---|---|
| 主基 | **ZFontManager**（功能覆盖最全，Windows 字体注册已实现），**仅保留 Windows**，裁掉 linux/macos 分支 |
| 零件来源 | **Evergarden**：移植 SQLite 索引 + SHA-256 文件哈希，补齐「十万级性能」与「哈希去重」两大缺口 |
| CJK 计数 | 把 Python 逻辑**用 Rust 重写**（ttf-parser 读 cmap 做区间统计），Python 版只当校验对照，不引入运行时 |
| 技术栈 | Tauri v2 + Rust + React 19 + TypeScript + Vite 7 + SQLite(rusqlite) |
| 许可证 | ZFontManager 是 **GPL-3.0**（衍生分发须 GPL-3.0）；Evergarden / CJK 是 **MIT**（可并入） |

## 2. 关键证据（决定路线的事实）

1. **ZFontManager 没有持久化字体索引**：`scanner.rs::scan_all` 每次启动 `WalkDir` 遍历后**逐个文件全量重新 parse**，100k 字体首启与每次启动都会很慢；`store.rs` 里只有 `state.json`（标签/集合/收藏/备注），**不含字体元数据、也没有文件哈希**。
2. **Evergarden 正好有这两块**：`db.rs` 建了 `fonts` 表并加了 `idx_hash`、`idx_family` 索引；`font_scanner` 用 `sha2` 算 `file_hash` → 增量扫描 + 哈希去重直接可用。
3. **裁剪点明确**：ZFontManager 有 **42 处 `target_os` 条件编译**，集中在 `activation.rs / adobe.rs / installer.rs / lib.rs / scanner.rs`；`scanner.rs` 里 linux/macos 的字体目录与 `managed_font_dir()` 分支可直接删。
4. **Windows 落地已具备**：`registry.rs` + `windows-sys`（`Win32_System_Registry`）实现每用户注册，无需管理员；`installer.rs` 自带备份。
5. **CJK 计数可低成本移植**：本质是「cmap codepoint 集合 ∩ 区间」，Rust 侧用 `ttf_parser::Face::cmap()` 枚举即可，不需要 fonttools。

## 3. 为什么不让 Evergarden 当主基

| 维度 | ZFontManager | Evergarden |
|---|---|---|
| 标签 / 集合 / 收藏 / 备注 | ✅ 全有 | ❌ 只有 `is_favorite`、`is_os_installed` |
| 激活 / 禁用（不删文件） | ✅ | ❌ |
| 去重 | ✅ 有 UI（按名称/样式/版本） | ⚠️ 有 hash 但无去重界面 |
| 回收站 / 备份 / 迁移 | ✅ | ❌ |
| SQLite 索引 + 文件哈希 | ❌ | ✅ |
| OpenType 深度检视 / 字体配对 | ❌ | ✅ |
| 许可 | GPL-3.0（传染） | MIT（宽松） |

**判断**：补齐 Evergarden 的组织层 + 激活 + 回收站，工作量明显大于给 ZFontManager 补 SQLite + 哈希。所以 **Z 做主基，E 做零件库**。

> **P5 已实现（2026-10-19）**：四项全部落地，**零新增外部进程/运行时**，压缩库纯 Rust 静态链入（exe 导入表仍只有 Windows 系统 DLL）。
> 1. **TTC/OTC 解包**：`sfnt.rs::read_face` + `build_sfnt`。按表搬移、tag 升序重排、4 字节对齐、重算 `head.checkSumAdjustment`；TTC 偏移按整文件绝对偏移处理；`DSIG` 丢弃（拆包后签名必然失效）。实测 msyh.ttc 拆出 Microsoft YaHei / Microsoft YaHei UI 两个独立 face。

> 3. **子集化 + WOFF/WOFF2**：`subset.rs`。字形闭包（含复合字形组件递归）→ 重编号 → 重建 glyf/loca/hmtx/hhea/maxp/head/cmap(format 4 + 12) → 丢弃带 glyph id 的表（GDEF/GPOS/GSUB/kern/hdmx/gvar…）。WOFF 走 zlib(flate2)，WOFF2 走 brotli，`glyf`/`loca` 用 transformVersion=3 的 null transform（完全合规）。**只支持 TrueType 轮廓**，CFF/OTF 明确报错而不是给坏结果。
> 4. **引用分析**：`reference.rs` + 侧栏「引用分析」页。PDF/AI/EPS 取 `/BaseFont`·`/FontName`；SVG/HTML/CSS/JS/Vue 取 `font-family`（JS/TS/JSON 要求带引号，否则 `fontFamily: titleFont` 会误报）；.sketch/.docx 等 zip 解开读 xml/json；PSD/INDD 等二进制按已装名做 ASCII + UTF-16LE 双向子串搜索。名字归一化后与已装字体比对（去子集前缀、削字重后缀、前缀匹配），输出「缺失字体 / 用到的已装字体 / 涉及文件」三份清单。

| **P8** | 使用统计（预览 / 安装 / 引用三类计数，「最近使用」「加入时间」两种排序）+ 文件夹规则（按厂商 / 语言 / 格式 / 分类归档，复制 / 移动 / 硬链接） | P2 / P7 | 归档先出方案再执行；系统字体与启用中的文件不许动 |

> **P8 已实现（2026-10-20）**：`usage.rs` + `organize.rs`，界面是侧栏底部两个新页面（使用统计 / 自动归档），既有布局未改。
> 1. **使用统计**：`cache.db` 里一张 `usage(family, kind, count, first_at, last_at)`，按 (family, kind) **聚合**而不是写事件流水 —— 一天点开同一款十次只让 `count` 加十，表不会越长越大。三类事件 `view`（打开整页详情）/ `install`（安装装载）/ `reference`（引用分析命中本机已装字体）分开计数。重扫、清索引都不碰这张表；`uninstall_font` 成功后顺手 `usage::forget`，别让统计页挂着已经删掉的名字。
> 2. **两个新排序**：`recent`（三类事件取最晚时间倒序，没用过的垫底）与 `added`（文件 mtime 倒序）。为了 `added` 给 `FontFace` 加了 `modified` 字段并把缓存 `user_version` 升到 4 —— 旧缓存没有这个字段，只能作废重解析一次。
> 3. **清理建议**：口径保守 —— 90 天没露面 + 没收藏 + 不在任何集合 + 单款 ≥ 1MB，只建「待清理」集合，一个文件都不动。
> 4. **归档先算后做**：`build_plan` 只读文件系统，把每一对「源 → 目标」摆出来给人看；`apply` 内部**重算一遍方案**再执行（防止预览之后文件又变了），单个失败不影响其它，最后逐条报。硬规则：`C://Windows//Fonts` 的字不动、目标目录不许落在 `%WINDIR%`、「移动」时正在启用的文件一律跳过（注册表指着原路径）。目标已有同名同大小文件时跳过而不是 `(2)`，所以「复制」按两次不会变成两份。

## 8. 风险与取舍

1. **GPL-3.0 传染**：ZFontManager 是 GPL-3.0，改造后若对外分发必须开源且同为 GPL-3.0；个人自用不受影响。若你希望保留闭源/宽松许可，则应改用 Evergarden（MIT）做基，但组织层要自己补。
2. **Node 版本**：Z 的 `engines` 要 24，需放宽 `package.json` 或升级 Node。
3. **十万级性能**：需实测。建议先造 5k / 2万 / 10万 三档样本压测，再决定缩略图缓存策略。
4. **woff2**：ttf-parser 不解 woff2 压缩，需引入 `woff2` 解码库。
5. **TTC 解包**：ttf-parser 只读单个 face，解包导出需额外解析 TTC 头（可参考 CJK 项目用 fonttools 的做法）。
6. **图标字体识别**：需检测 `liga`/PUA 区，作为启发式规则，不保证 100%。
