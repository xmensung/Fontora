## 一、结论先行

1. Anyway.Fonts 是**浏览器里的中文字体挑字工具**，靠 Chrome 的 Local Font Access API 读本机字体，
   字体文件不上传，本地解析。它的功能全部围绕「挑一款中文用字」这一件事。
2. 它最值得抄的是**三件具体交互**：缺字检测（标红 + 计数徽章 + 只看不缺字）、竖排预览、
   叠层对比。这三样正好是 Fontora 现在缺的，且实现成本都不高。
3. 评论区一共只提出 4 个有效诉求，其中两个对 Fontora 价值很高：
   **把字体库通过 MCP / Skill 暴露给 Agent**（作者已回复「已添加初版」）、
   **一键识别字体标准（GB2312 / GBK / GB18030-2022）**。
   另外两个是「离线版」和「收藏分类」——前者是 Fontora 的天然优势，后者已有集合功能覆盖。
4. 它的很多能力在浏览器里是变通实现（缺字靠读字符表 + 系统字体代显、竖排靠 CSS、样张靠模板拼），
   Fontora 有 Rust 原生后端，**同样的功能可以做得更准**，还能做出它做不到的（真判定字符集标准、
   按轮廓对齐的叠层、批量缺字审计）。
5. 不建议抄：登录同步收藏、赞助入口、浏览器授权流程。这些是它的约束条件带来的，不是功能亮点。

## 二、Anyway.Fonts 功能全清单

### 1. 字体来源与权限

| 功能 | 说明 |
|---|---|
| 读取本机字体 | 点击授权后由浏览器 Local Font Access API 提供，字体不上传 |
| 浏览器限制 | 仅桌面 Chrome / Edge 可用；Safari、Firefox、手机浏览器不支持 |
| 登录同步 | 邮箱 magic link 登录，只同步收藏的字体名；不登录则收藏仅存本地 |

### 2. 列表与筛选（左侧栏 + 顶部）

| 模块 | 内容 |
|---|---|
| 库入口 | 全部字体、我的收藏、最近看过 |
| 收藏分组 | ＋新建分组、管理分组；同一款字体可进多个分组；悬浮星星或右侧收藏按钮选分组 |
| 文字范围 | 全部 / 中文 / 西文；细分 简体中文、繁体中文、日文、韩文 |
| 中文风格 | 黑体、宋体、楷体、仿宋……（按字体名整理，带数量） |
| 字体特征 | 可变、多样式、等宽、开源、大字符集 |
| 搜索 | 输入即筛，`/` 聚焦 |
| 排序 | 名称 A–Z、名称 Z–A、样式数量、随机、按出品方、收藏置顶 |
| 视图 | 列表 / 网格切换；每行右上有「N 个样式」+「对比」按钮 + 收藏星 |

### 3. 缺字检测（核心卖点 01）

- 每行预览用当前字体渲染示例文本，**该字体缺的字直接标红**，并用系统字体代显（看得出来缺成什么样）。
- 行首徽章：`缺 4 个字符` / `这句不缺字`。
- 顶部开关「只看不缺字」——一键筛掉所有不能完整渲染当前文本的字体。
- 说明文案：缺字检测直接读取当前字体的字符表；字符表检测不代表连字、组合字符或彩色表情能正确排版。

### 4. 预览与试字

| 控件 | 说明 |
|---|---|
| 字号 | Aa 滑杆，36 px（范围可调） |
| 行高 | 1.35 倍，独立可调 |
| 预览文本分类 | 中文（现代文 / 繁体中文 / 偏旁部首 / 基础笔画 / 常用标点）、字母（Lorem ipsum / Quick fox）、数字、其他（日文 / 韩文） |
| 自由输入 | 任意文本即时重渲染 |
| 历史 | 记录用过的预览文字，可清空 |

### 5. 竖排预览（卖点 03）

- 中文竖排渲染，标点位置按竖排规则调整。
- 视频里的呈现：同一句「永夜一禅子，泠然心境中。」横排三列对比宋体 / 黑体 / 仿宋。
- 站点自称「（可能是）东半球最方便竖着挑字的在线工具」。

### 6. 字体详情（三标签页）

| 标签 | 内容 |
|---|---|
| 试字 | 大字号试字区 + 字号行高控制 |
| 样张 | 自动生成的版式样张，标注「自动生成，非厂商官方样张」；四种版式轮换（见下）；右上「换一组」 |
| 信息 | 中文名 / 英文名 / 出品方 / 样式数 / 授权信息 / 字符集覆盖情况 |

样张的四种版式（视频逐帧可见）：

1. `TYPE SPECIMEN` —— 大字标题「文字有声」，配 FORM / RHYTHM / VOICE 小标。
2. `READING NOTES / 03` —— 正文阅读版式，「文字的日常」+ 一段 60 字左右的现代文，看行气。
3. 竖排诗签 —— 「如诗 日常」竖排 + 一枚印章 + 荷花插图，编号 No.014。
4. `字形地貌 TOPOGRAPHY` —— 同一个「山」字排成 20 格矩阵，看同一字在不同字号下的轮廓差异。

### 7. 字体对比（卖点 04）

| 模式 | 说明 |
|---|---|
| 并排 | 多列并排，同文本同字号 |
| 逐行 | 上下逐行堆叠，便于逐行看细节 |
| 叠加 | 多字体同字重叠（半透明叠色），**可拖动对齐、可重置** |

- 流程：列表行 →「对比」→ 已加入对比（计数）→ 开始对比 / 全部清空。

### 8. OpenType 字形特性

- 展示可直接读取的字形替换（如 smcp / onum / frac 之类的样例字形）。
- 附「OpenType 特性指南」+ W3C 文档外链。
- 明确免责：上下文、定位、可变字体规则可能展不开；没有示例不代表字体没这功能。

### 9. 其他

| 功能 | 说明 |
|---|---|
| 深浅色主题 | 跟随系统 / 浅色 / 深色 |
| 字体读取详情 | 哪些字体解析失败、可重新读取；解析失败仍可能正常预览 |
| 赞助 | Stripe 收款，微信 / 支付宝 / 银行卡，¥10 / ¥20 / ¥50 / 自定义 |
| 更新历史 | 站内更新日志（最近一条：收藏可以分组了） |

## 四、Fontora 现状对照

图例：**有** = 已具备且不弱于对方；**半个** = 有数据没界面，或只有简版；**无** = 没有。

| 能力 | Anyway.Fonts | Fontora | 差距性质 |
|---|---|---|---|
| 缺字检测（标红 + 计数 + 筛） | 有 | **无** | 数据齐（`get_charset`），只缺交互 |
| 只看不缺字 | 有 | 半个（只有「包含此字符」） | 把单字扩成整段即可 |

## 五、建议加什么

### P0：低成本、高感知（建议先做，2～3 天量级）

**1. 缺字检测三件套**

- 列表行内：预览文本里该字体缺的字用红色/下划线标出，并用 fallback 字体代显（缺成什么样一目了然）。
- 行内徽章：`缺 4 个字符` / `这句不缺字`。
- 筛选开关：`只看不缺字`，与现有「包含此字符」合并成一个「文本覆盖」筛选组。
- 实现：`get_charset`（`lib/ipc.ts:606`）已有的码点数组与 `sampleText` 求差，纯前端即可；
  批量场景（全库体检）可以放到 Rust 侧一次算完。这个功能正好接上 0.9.0 刚做的标签与筛选体系。

**2. 预览文本预设 + 历史**

- 分组：现代文 / 繁体 / 偏旁部首 / 基础笔画 / 常用标点 / 日文 / 韩文 / Lorem ipsum。
- 历史记录条（最近 N 条，可清空），随 `state.json` 持久化。
- 纯前端，`TopBar` 的 `sampleText` 输入框旁边加一个下拉即可。

**3. 预览字号 / 行高直调**

- 顶部加 Aa 滑杆（字号）+ 行高倍数，作用于列表行、瀑布流、详情试字区，存进 prefs。

### P1：中等成本、差异化（1～2 周量级）

**4. 竖排预览**

- `writing-mode: vertical-rl` + `text-orientation: mixed`，西文自动直立、中文标点按竖排规则；
  可挂一个「横排 / 竖排」切换在详情试字区和列表行。
- 注意点：字体本身没有 `vmtx` / `VORG` 时由浏览器合成，行距要留够；标点挤压不考虑也够用。

**5. 叠层对比**

- 现有 `CompareOverlay.tsx` 只有并排三档字号，加两个模式：逐行、叠加。
- 叠加做法：两个 `@font-face` 同字符绝对定位重叠，浅色主题 `mix-blend-mode: multiply`、
  深色 `screen`，配一个透明度滑杆 + X/Y 偏移 + 「重置」；不用轮廓对齐也能看出骨架差异。

**6. 自动样张（多版式）**

- 新增 `SpecimenBoards.tsx`，四套版式：海报标题 / 竖排诗签 / 正文阅读 / 字形矩阵，
  内容池随机取（文案、日期、编号、署名），「换一组」重新采样。
- 每张样张底部固定一行「自动生成，非厂商官方样张」，避免被当成厂商物料。
- 导出走现有 `lib/specimen.ts` 的 canvas 链路。

**7. 中文风格筛选**

- 顶部筛选加「中文风格」组：黑体 / 宋体 / 楷体 / 仿宋 / 圆体 / 隶书 / 篆书 / 行书 / 草书。
- 直接复用 0.9.0 的 `tagTaxonomy.ts` 分组词表与 `tagSuggest.ts` 的族名关键词规则，
  没有手动标签的字体用推导结果兜底，标注「自动判定」。

### P2：工程量大、能拉开代差（按需排期）

**8. MCP / Skill：把字体库交给 Agent**

- 这是评论区最高赞建议，也是 Fontora 相对网页工具的绝对优势——库、标签、路径都在本地。
- 形态：`src-tauri/src/bin/fontora-mcp.rs`，stdio JSON-RPC，复用 `db.rs` / `lib.rs` 的查询函数。
- 工具集建议：`list_fonts(kind/tag/standard)`、`search_fonts(query)`、`font_detail(family)`
  （规格 / 许可 / 覆盖）、`missing_glyphs(family, text)`、`render_sample(family, text, size, vertical)`
  返回 PNG、`suggest_by_tags(tags, limit)` 按标签配字。
- 这一步做完，Agent 做设计时能直接问「我库里适合做民国海报的宋体有哪些，帮我排一版竖排小样」。

**9. 字符集标准判定（GB2312 / GBK / GB18030）**

- Rust 侧新增 `charset_standard.rs`：内置三套标准的分级码表（GB2312 6763 字 / GBK 20902 字 /
  GB18030 全量），与字体 cmap 求差，输出「符合 GB2312 / GBK，GB18030 差 132 字」这类结论。
- 比浏览器方案准得多：可以直接读 cmap，不依赖"字符表能不能渲染"的近似判断。
- 顺带能做成「全库按字符集标准分组」，采购字体时很有用。

**10. 字体来源与完整性**

- 回应「怕网上下载的免费商用字体被暗改」：已有 SHA-256，再加一层
  「首次见到的指纹 / 与记录不一致时告警」，配来源备注（官网 / 网盘 / 客户提供）与授权字段。
- 导出字体包时带上指纹清单，交付给别人可校验。

**11. OpenType 特性可视化**

- `get_features` 已有数据但没有界面。在详情页加一格：按特性分组（连字 / 小型大写 / 旧式数字 /
  分数 / 花体替代）给出开关式示例字形，开关切换即渲染对比。

### 不建议抄

| 项 | 原因 |
|---|---|
| 登录 / 邮箱同步收藏 | Fontora 是本地优先工具，账号体系只会增加负担；`Data\` 拷走就是同步 |
| 赞助入口 | 个人项目不需要；真要放也是官网，不占软件界面 |
| 「读取本机字体」授权流程 | 原生应用直接扫目录，无需浏览器授权，这是优势不是缺口 |
| 站点式落地页 / 引导动画 | 桌面软件首次启动已有 Onboarding，不需要营销页 |

  其余需 wbi 签名 + 登录态，多次重试触发 -352 风控。已覆盖有信息价值的全部条目。
- 原始数据：`reports/anyway-video/comments_full.json`、`site.html`、`contact.png`、`f_*.png`。
