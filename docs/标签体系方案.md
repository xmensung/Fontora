# 标签体系方案（Fontora）

写在前面：这份文档只谈"标签该怎么分"，不谈界面怎么画。界面按方案 B 已经把
书体、范围、特征搬到了左栏，那是"软件自己判定"的部分；本文要解决的是剩下那部分
——只有人或 AI 才能判断的东西。

## 一、先看别人怎么分

翻了几个主流产品，做法出奇地一致：把「客观属性」和「主观描述」分成两套，绝不混在
一个标签池里。

| 产品 | 客观层（软件/标准判定） | 主观层（人给的） |
|---|---|---|
| Adobe Fonts | Classification 八类（Serif、Sans、Slab、Script、Blackletter、Monospaced、Display、Symbol）+ Properties（字重、宽度、x 高、对比度、数字样式） | Tags：Friendly、Rough、Futuristic、Clean、Luxurious、Wedding、Art Deco、Western |
| RightFont | 自动分类 + Smart Tags（按规则生成） | 手动 Tags，可拖拽 |
| Typeface | Filters（语言、风格、字重）+ 重复检测 | 嵌套标签、Quick Collection（临时候选池） |
| FontBase | Collections、嵌套文件夹、监视文件夹 | Tags |
| Extensis Connect Fonts | 自动字体冲突检测 | 批量打标签、团队共享与权限 |

Adobe 官方那篇讲 Font Tags 的博客里有一句关键的话，大意是：**用户和客户根本不用
字体术语描述需求，他们说的是"想要活泼一点""要有未来感""像婚礼请柬"**。所以他们
才在分类和属性之外，单独做了一层情绪化的标签。

这条结论直接决定了 Fontora 该怎么分：分类和属性交给软件，情绪和用途交给标签。
现在的 `tagTaxonomy.ts` 把这两类混在一起了 —— `origin` 组（宋体/黑体/西文衬线）
是分类，`attrs` 组（等宽/可变字体/大字库）是属性，只有 `mood` 组才是真正的标签。

## 二、三层模型

### 第 1 层：软件自动判定，不进标签

这些从字体文件或族名就能读出来，让 AI 或用户去标是浪费。

- 范围：中文 / 西文
- 书体：宋 / 黑 / 楷 / 仿宋 / 圆 / 隶 / 篆 / 行草 / 其他
- 特征：可变、多样式、等宽、大字符集、OpenType 特性、文件格式

这一层对应左栏的「字体范围」「中文书体」「字体特征」三段，已经在做。

书体是"猜"出来的（读族名关键词），会有错判。留一个补救口：允许用户手动改某款
字体的书体，存下来覆盖猜测结果。这比让用户给每款字体打一遍"宋体"划算得多。

### 第 2 层：受控词表，AI 或人工打

真正的标签。每组控制在 8–12 个，全部加起来不超过 30 个 —— 超过这个数，词表本身
就失去了检索价值，用户会开始自己造词。

**用途（这个字体适合干什么）**

正文、标题、海报、标志、界面、包装、书籍、视频字幕、游戏、请柬

**气质（看上去什么感觉）**

优雅、现代、复古、活泼、严肃、柔和、硬朗、手写、科技、童趣、奢华、粗犷

**风格（什么流派/年代，可选，只在需要时开）**

几何、装饰、像素、国风、工业、新艺术

### 第 3 层：自由标签

用户自己加的词，一律归入侧栏的「其他」。

必须有配套的「合并同义标签」：把"复古 / 怀旧 / 复古老 / retro"合并成一个。
没有这个功能，自由标签半年后必然泛滥，这是 Eagle 一类素材管理软件最常见的
退化路径。

## 三、和现在实现的差异

| 现有分组 | 处理 |
|---|---|
| `origin`（宋体、黑体、西文衬线…13 个） | 删除。与左栏书体筛选重复，且用户不会用标签表达"这是宋体" |
| `mood`（正文、标题、复古、商务…10 个） | 拆成「用途」和「气质」两组。现在把"正文"（用途）和"复古"（气质）混在一起，筛选时语义打架 |
| `attrs`（等宽、斜体、可变字体、大字库…8 个） | 删除技术项，交给「字体特征」。保留"繁体支持""生僻字支持"这类读不出来但确实要筛的 |

删掉的分组不会丢数据：标签在存储层就是纯字符串（`family → tags[]`），分组只是
前端的常量映射。删了分组，已有标签自动落到「其他」，用户看得见、带得走。

## 四、让 AI 打标签的完整链路

现在只做了最后一环（`importAiCatalog` 回读 JSON）。缺前半段：

1. **导出待标注清单**：选中一批字体（或整个库），导出成表格
   字段：family、厂商、分类、书体猜测、语种、字重数、字形数、文件路径
2. **生成提示词**：软件附带受控词表，生成一段可直接粘贴的 prompt，例如
   "以下是 50 款字体的元信息，请从给定的用途/气质/风格词表里为每款选 1–3 个标签，
   只输出 JSON 数组，不要解释"
3. **回读结果**：AI 返回 `[{"family":"…","tags":["正文","优雅"]}]`，导入
4. **审核后写入**：导入时先在列表里预览命中情况（哪些家族名对不上、哪些词不在
   词表里），确认后再合并进现有标签，避免 AI 幻觉污染数据

第 4 步很重要。AI 编出来的家族名（多一个空格、少一个 "Pro"）如果直接写入，会变成
一堆指向不存在字体的孤儿标签，且很难清理。
